# Constraints — [שם הפרויקט]

> **חוק הזהב:** כל אילוץ חייב חלופה.
>
> פורמט: `אל תעשה X. תעשה Y במקום, כי Z.`
>
> אילוץ ללא חלופה גורם לאייג׳נט להיתקע או להמציא פתרון גרוע.

---

## אבטחה

- **אל תשמור סודות בקוד.** תשתמש ב-environment variables ותיצור `.env.example` עם שמות המשתנים (בלי ערכים), כי git history חשוף לכל מי שיש לו גישה ל-repo.
- **אל תשתמש ב-localStorage לטוקני auth.** תשתמש ב-httpOnly cookies במקום, כי localStorage חשוף להתקפות XSS.
- **אל תסמוך על קלט משתמש.** תאמת ותסנן בגבולות המערכת (API endpoints, form inputs), כי קלט לא מאומת = injection vulnerability.
- **אל תלוג PII / סיסמאות / טוקנים.** תלוג רק מזהים או hash, כי לוגים נשמרים ארוך טווח וחשופים לצוותים שונים.

## ארכיטקטורה

- **אל תשכפל לוגיקה שכבר קיימת.** חפש utility/helper/hook לפני כתיבה חדשה, כי DRY threshold = 3 (שני שכפולים בסדר, השלישי = extract).
- **אל תוסיף dependency חדש בלי הצדקה.** בדוק אם < 20 שורות קוד עצמאי יספיקו, כי כל package = maintenance debt + bundle size.
- **אל תיצור circular dependencies.** אם A → B ו-B → A, restructure, כי זה סימן לארכיטקטורה שבורה.
- **אל תשנה חתימת פונקציה/API ציבורי.** הוסף פונקציה חדשה או פרמטר אופציונלי, כי שינוי חתימה שובר את כל הקוראים.

## Scope & Scope Creep

- **אל תרחיב scope בתיקון באג.** תקן רק את הבאג. אם ראית משהו אחר בעייתי — flag ל-learnings.md, כי Eager Editor = 52 קבצים במקום 1.
- **אל תשנה סגנון/פורמט של קוד קיים שלא נגעת בו.** גם אם הוא מכוער, כי diff מתנפח ו-review נהיה בלתי אפשרי.
- **אל תמציא מבני קוד חדשים.** קרא 2-3 קבצים סמוכים ועקוב אחרי אותו דפוס, כי Pattern Breaker שובר את הארכיטקטורה הקיימת.
- **אל תוסיף פיצ׳ר שלא ב-PRD.** גם אם "הגיוני" או "כולם עושים את זה", כי scope creep = deadline miss.

## UX

- **אל תקודד רק happy path.** לכל פעולה — הוסף loading state, error state, empty state, success state, כי משתמש תמיד יגיע למצב לא צפוי.
- **אל תתחיל מ-desktop ואז "נתאים למובייל".** תתחיל mobile-first ותגדיל, כי scale up קל מ-scale down.
- **אל תוסיף RTL אחרי הפיתוח.** תשתמש ב-logical properties (margin-inline-start, לא margin-left) מהשורה הראשונה, כי bolt-on RTL יוצר באגים גרפיים ארוכי טווח.
- **אל תציג הודעות שגיאה כלליות.** תגיד מה נכשל, למה, ומה לעשות, כי "Something went wrong" = חוסר אונים למשתמש.

## Testing

- **אל תכתוב טסטים שמסתכלים על אימפלמנטציה.** תכתוב טסטים שמודדים התנהגות מ-PRD, כי טסטים שמחוברים לאימפלמנטציה שוברים על כל refactor.
- **אל תדלג על טסטי edge cases.** null, undefined, empty, zero, boundary values — חובה, כי שם נופלים רוב הבאגים.

## AI / Agent Work

- **אל תכתוב קוד לפני שיש plan.md מאושר.** אפילו שורה אחת, כי קוד בלי תכנית = אימפלמנטציה שלא מתאימה לארכיטקטורה.
- **אל תעדכן progress.md או learnings.md בעצמך בלי שהמשתמש ידע.** דווח במפורש מה עדכנת, כי מעקב אילם = loss of trust.
- **אל תשתמש ב-subagent לקוד קריטי בלי review.** subagent יכול להמציא — תמיד בדוק את הפלט, כי אחריות סופית = שלך.
